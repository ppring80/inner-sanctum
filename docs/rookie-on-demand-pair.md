# Explicit on-demand Rookie pair opinion

A customer may explicitly request a second opinion on two named players even when SAGE has decided. This fixes the saved-only/unresolved restriction without restoring full-lineup generation. SAGE remains the decision authority and no lineup is modified.

The connected lineup reply includes an invitation with an actual starter/comparator pair: “Want another take? Ask ‘Rookie, [player] or [player]?’” It explains that the service uses Anthropic with permission. A broad second-opinion request without a ready saved answer returns CHOOSE_PAIR instead of saying the customer cannot obtain a review. The host asks which two players. This invitation is in the connected MCP flow; no website rollout or separate marketing announcement is included.

The new request_rookie_second_opinion tool requires the latest linked decisionId, two exact roster names and explicit consent to send their football evidence to Anthropic Claude Sonnet. Consent is checked before reading evidence. An owner-scoped pointer written during the ordinary linked lineup capture rejects older decisions. Record, parent and focused hashes are verified. Both players must be eligible for one common slot; SAGE’s existing comparison slot is preferred. No unresolved-state requirement applies to this explicit request.

The existing qualified structured-pair schema, deterministic renderer, provider deadline, atomic five-slot daily selected-pair budget and request cache are reused unchanged. No retries, new allowances or resets. Invalid answers, unavailable players selected, stale evidence, timeouts or exhausted limits return unavailable with the lineup unchanged. Public output excludes raw provider replies and evidence/storage keys. Confidence is described as the model’s assessment rather than a guarantee. Paid diagnostics remain separate; full-lineup invocation remains rejected.

Offline tests cover decided-slot success, duplicate cache reuse, the existing cap, consent before evidence reads, owner/current record/hash and eligibility gates, timeout isolation, private output, actual tool registration, and customer invitation/CHOOSE_PAIR behavior. The tests use mocked providers only. Full CI is required before merge. No paid live qualification is included in this implementation; deployed generation must still be exercised with a named pair and explicit transfer consent.
